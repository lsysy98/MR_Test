# 테스트 검색 정리 · 알림 버전 (2026-09-18)

## 이번 업데이트 적용

1. 테스트 Supabase에 갱신된 `test-search-notifications.sql`을 한 번 실행합니다. 이번에는 알림 시간 컬럼과 예약 함수가 추가되어 이전 파일을 실행했어도 한 번 더 필요합니다. 기존 보고·구독은 유지합니다. 안정화 SQL과 schema.sql은 다시 실행하지 않습니다.
2. 이 ZIP을 테스트 Vercel에 배포합니다. 메뉴에 **거래처 정리**, **알림 설정**이 추가됩니다.
3. 거래처 정리의 관리자 키는 기존 테스트 Vercel 환경변수 `ADMIN_KEY` 값입니다. 별도로 만든 비밀번호가 아닙니다. 키를 모르면 정리는 건너뛰어도 알림 설정과 무관합니다. 이 SQL 실행만으로 데이터가 삭제되지는 않습니다.
4. 알림 환경변수가 이미 등록되어 있으면 그대로 유지합니다. 처음 설정할 때만 아래 변수를 테스트 Vercel Production에 등록합니다.
5. 배포 후 메뉴 > 알림 설정에서 본인 이름과 시간을 저장합니다. 기존 서버 설정으로 Supabase 예약 작업을 자동 연결하므로 추가 키 복사가 필요하지 않습니다.

| 변수 | 값 |
|---|---|
| PUSH_ENABLED | `true` (중지하려면 `false`) |
| PUSH_SITE_ORIGIN | 실제 테스트 사이트의 `https://...` 주소. 경로 없이 입력 |
| VAPID_PUBLIC_KEY | 설정 안내에서 생성한 공개키 |
| VAPID_PRIVATE_KEY | 같은 안내에서 생성한 비밀키. 브라우저 코드나 ZIP에 넣지 않음 |
| CRON_SECRET | 설정 안내에서 생성한 예약 실행 전용 비밀키 |

- 원본 사이트, 원본 DB, 원본 ZIP은 변경하지 않습니다. 영업계획서 전송도 계속 차단됩니다.
- CIMS I열의 오스템/오 스템/(거래종료) 표기, L열의 폐업을 제외합니다. 기존 기공소·지점 외 사업장 제외도 유지합니다. 휴업, 담당자 미기재, 코드 없는 신규 치과는 자동 제외하지 않습니다.
- 정리 전 후보는 50개씩 표시합니다. 15분 뒤 만료되며, 확인 이후 변경된 행은 삭제하지 않습니다. 삭제 전 행을 별도 비공개 테이블에 보관합니다. ‘이전 정리 확인’ 후 ‘이번 정리 복구’로 복구할 수 있으며, 이후 재등록된 행은 덮어쓰지 않습니다.
- 재수입과 시트 대체 조회에도 같은 제외 규칙을 사용합니다. 정리 시 보고, 담당자-지점 매핑, 기존 거래처 표시 자료는 변경하지 않습니다.
- 알림 담당자와 시간은 이 기기에서 별도로 지정합니다. 기본값은 한국시간 18:00이며 00:00~23:59에서 분 단위로 선택합니다. 보고 입력란의 담당자를 바꿔도 바뀌지 않습니다. 기기마다 직접 알림 허용이 필요합니다.
- Android Chrome은 웹사이트 알림, iPhone/iPad는 iOS/iPadOS 16.4 이상 홈 화면 웹앱에서 사용합니다. 미지원·거부 상태를 안내하며 알림 허용을 강제로 요청하지 않습니다.
- Supabase Cron이 매분 확인하고 보낼 대상이 있을 때만 테스트 서버에 요청합니다. Vercel의 하루 한 번 예약은 제거했습니다. 연결 키는 Supabase Vault에 저장합니다. [공식 안내](https://supabase.com/docs/guides/functions/schedule-functions)
- 선택한 시간 이전에는 보내지 않습니다. 지연 시 15분까지만 재확인하고 이후에는 당일 알림을 건너뜁니다. 이미 알림을 받은 날에는 시간을 바꿔도 다시 보내지 않습니다. 자정이 지나면 전날 알림을 보내지 않습니다.
- 사이트가 열려 있지 않아도 발송하지만 통신·알림 권한·집중 모드 등의 영향을 받습니다. 페이지나 보고 API를 오프라인 캐시하지 않습니다.
- 주말·기존 공휴일·직접 설정한 휴일·연차·완료자는 제외하고, 직접 지정한 근무일은 포함합니다. 공휴일 표는 기존 화면과 같은 2026~2027년 범위입니다. 이후 연도는 공휴일 표 갱신 전까지 직접 지정한 근무일에만 발송합니다.
- 발송 직전에 완료와 구독 상태를 재확인합니다. 기기별 당일 중복 요청은 DB에서 차단합니다. 시험 알림은 분당 한 번입니다.
- 404/410 만료 구독은 비활성화합니다. 실패는 `report_push_deliveries`에 기록하고 15분의 발송 가능 구간 안에서 다음 예약 확인 때 최대 3회 시도합니다. 전송 여부가 불명확한 중단 요청은 자동 재전송하지 않습니다.
- 푸시 endpoint·인증 토큰·비밀키는 브라우저 응답과 로그에 노출하지 않습니다. 공개 API에서는 공개키와 해당 기기의 연결 상태만 반환합니다.
- 테스트 서버 배포, SQL 실행, 실제 기기 수신은 사용자가 마지막으로 확인해야 합니다. 로컬 검증은 가짜 데이터와 가짜 발송기로 수행하며 실제 영업계획서나 푸시 서비스로 보내지 않습니다.

## 이전 안정화 업데이트 (2026-09-17)

## 적용 순서

1. 기존 **테스트 Supabase**의 SQL Editor에서 함께 제공된 `test-stability-upgrade.sql`을 한 번 실행합니다.
2. 이 ZIP을 **테스트 Vercel 프로젝트**에만 배포합니다.
3. 사이트를 새로고침합니다. 기존에 열어둔 탭도 새로고침해야 합니다.

이번 업데이트에는 기존 `schema.sql`을 다시 실행하지 않습니다.
원본 프로젝트와 원본 Supabase에는 적용하지 않습니다.
이전 안정화 기능만 사용할 때는 추가 환경변수가 필요 없습니다. 이번 웹 알림은 위 환경변수가 필요합니다.

## 변경 내용

- 저장 요청 ID를 유지하여 재시도 시 중복 등록을 막습니다.
- 보고 변경, 변경 기록, 전송 대기 기록을 하나의 DB 트랜잭션으로 저장합니다.
- 성공사례와 통계수거 완료 처리는 해당 필드만 수정합니다.
- 편집을 시작한 뒤 다른 곳에서 수정된 보고/전시회는 덮어쓰지 않고 충돌을 알립니다.
- 전시회 저장/삭제는 모든 날짜와 참석자를 한 번에 처리합니다. 중간 오류 시 기존 데이터가 유지됩니다.
- 거래처코드는 **CIMS 치과명 + 입력된 지점**이 일치할 때만 변경 후보로 제시합니다.
- 띄어쓰기와 의원/병원 표기 차이만 무시합니다. 부분 문자열이나 처방통계의 코드로 보고를 자동 변경하지 않습니다.
- `메뉴 > 코드확인 > 연결 변경 미리보기`에서 변경 전후를 확인하고, `수정하기 > 수정 저장`으로 적용합니다.
- 지점이 없거나 후보가 여러 개면 기존 값을 유지하고 확인 대상으로 남깁니다.
- 검색어 삭제/변경/선택 시 오래된 결과를 무효화합니다.
- 월간 검색 결과 클릭 시 신규/증대 필터를 해제하고 해당 거래처로 이동합니다.
- 전시회 목록은 메뉴를 열 때만 불러옵니다. 보고 화면은 휴일/완료 상태 응답을 기다리지 않고 먼저 표시합니다.
- 보고 조회가 1,000건에서 잘리지 않습니다.
- 만원 입력의 소수점 4자리까지 보존합니다. 예: 1.5 = 15,000원, 0.0001 = 1원.
- 모바일 크게 보기의 가로 넘침을 수정했습니다.

## 영업계획서 연동 차단

**이 테스트 버전은 URL과 API 키가 설정되어 있어도 영업계획서로 전송하지 않습니다.**

테스트 DB에는 보고 변경의 전송 대기 기록이 쌓이지만, 외부 전송과 재시도 API는 계속 비활성화되어 있습니다.
`lib/outbox-worker.js`는 향후 원본 적용 때 사용할 서버 작업 코드이며 현재 테스트 API에서는 실행되지 않습니다.
이 파일은 가짜 수신처와 로컬 DB로만 검증했습니다. 실제 상대방 사이트와의 전송은 검증하지 않았습니다.

원본으로 올리기 전에는 별도 승인 후 서버 작업 실행 방식과 인증, 스케줄을 설정해야 합니다.
**테스트 DB의 대기 기록을 원본으로 복사하거나 테스트 전송 차단을 해제하면 안 됩니다.**

## 백업

서버의 기존 관리자 키로 `/api/backup?key=관리자키`에 접근합니다.
백업은 `.json.gz` 압축 파일입니다. 압축을 해제하면 JSON 안의 `tables`에 다음 자료가 포함됩니다.

- 보고, 변경 기록, 보고 완료/연차, 휴일
- 전시회, 날짜, 참석자
- 거래처 목록, 담당자-지점 연결, 기존 거래처 표시 자료
- 전송 대기 기록, 중복 요청 방지 기록

백업에는 업무 정보가 포함되므로 공개 공유하지 않습니다. 비밀번호나 서버 환경변수는 백업에 넣지 않습니다.

## 검증

실제 PostgreSQL 기반 로컬 SQL 테스트, 서버 API 테스트, Chrome/Playwright 화면 테스트를 실행했습니다.
원본 파일과 원본 ZIP은 수정 전후 SHA-256을 비교합니다.
실제 Vercel 배포 및 원격 Supabase SQL 실행은 별도 단계입니다.
